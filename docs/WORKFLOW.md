# TikTok 本地化流水线 · 当前完整工作流程

> 这份对应**正在运行的实现**（插件 `@local/tiktok-localizer`），不是设计稿。每一节末尾标了对应文件，方便你指出修改点。

## 0. 入口

| 入口 | 能力 |
| --- | --- |
| 左侧栏「视频本地化」面板 | 粘贴链接、开始/停止、逐条进度、封面缩略图、每条质检结果 + 「按建议修改 / 保持现状」、在访达打开；顶部「新建对话」「历史对话」「历史批次」 |
| 工具 `tiktok_localizer` | `start` 提交批次 · `status` 看进度与质检 · `qc` 对已有成品补检（含视觉审片） · `fix`（`scope=all\|subs`）按建议返工 · `retry` 重跑失败条目 · `history` 历史批次 · `chats` 历史对话 · `stop` · `open` |

## 0.5 面板快捷入口

- **新建对话**：在 `/Volumes/Data/媒老板` 工作区开新会话，并预填「用 tiktok_localizer 处理新一批 TikTok 链接：」。
- **历史对话**：列出最近 40 个会话（标题 + 日期 + 「打开」），点击直接切到该会话；数据来自宿主 `sessionQuery.listSessions` + 标题快照，跨重启可用。
- **历史批次**：读输出目录下的 `批次-*`，显示条数 / 完成 / 质检待改 / 不合格 / 失败，可一键在访达打开。

## 1. 输入解析（`index.js: normalizeInputs`）

- 每行：含 `http(s)` 视为链接，否则视为本地文件/目录；支持整段分享文本。
- **严格按粘贴顺序逐条处理**（并发固定为 1），序号 = 输入顺序，成品文件夹编号与之绑定。

## 2. 取片（`index.js: acquireVideo / download*`）

```
本地路径 → 直接用
链接    → yt-dlp（浏览器指纹模拟）→ tikwm（1.3s 限速、3 次重试）
```

- 代理：`proxy` 留空时每次下载前探测 `127.0.0.1:7890`（FlClash）；无代理会明确提示。
- 重试/返工：`_work/N/source.mp4` 存在则复用，不重复下载。
- 单条失败只记录原因，不中断整批。

## 3. 识别（`runtime/analyze.py`）

- 抽帧 4fps、缩放到 720；macOS Vision OCR（默认 `ja-JP,ko-KR,en-US`，6 进程并行）。
- 事件聚类：相似度 ≥0.75、纵向接近、持续 ≥2 帧且 ≥0.3s；坐标换算到源分辨率。
- **ASR 已停用**：只做画面 OCR，不做任何语音识别（`analyze.py --ocr-only` 恒开，whisper 不会被启动）。
  - 音轨平均 < -50 dB 直接跳过（避免噪声编字）；
  - VAD 段数过少时改整段识别。
- 只对音轨做**能量检测**（不跑识别、几毫秒）：判断“有没有朗读”。
- 有朗读但几乎没画面字幕 → 判**不合格·建议替换或人工补字幕**（ASR 停用后不再自动转写）。
- 产物：`probe.json` `ocr.jsonl` `events.json` `asr.json` `review.txt` `summary.json`（含 `captionEvents`、`captionCoverage`、`hasSpeech`、`noSpeechNoCaptions`）。
- **无画面字幕判定**：覆盖率 <15% 或画面字幕 <3 条 → 该条标「⚠ 无画面字幕」，不硬凑字幕，面板/状态可见。

## 4. 翻译与文案（`index.js: translate*`）

- ≤60 条事件：一次调用；>60：按 45 条分块翻译画面文字 + 一次生成标题正文；调用失败自动二分重试；单次调用 180s 超时。
- 产出 `_work/N/zh.json`：

```json
{"language":"ja","vertical":"美妆","brand":"资生堂","model":"HAKU","rejected":false,"title":"…","body":"…","coverT":3.2,
 "overlays":{"12":"…"},"drop":[4],"promo":[7],
 "extra_subs":[{"t0":1.2,"t1":3.0,"zh":"…","src":"…"}]}
```

- 提示词规则：
  - 单行、无标点、每条 ≤20 汉字；中文里**不允许出现韩文/日文原文**；
  - 画面大标题、花字、信息卡必须逐条翻译；
  - **只把需要抹掉的放进 promo**：账号名/平台标识（Instagram/YouTube/小红书等）/品牌活动或合作标签（#ad、#협찬）/关注点赞收藏转发引导/价格条；普通讲解、字幕、产品名是内容，必须翻译；promo 一般 ≤ 事件总数 1/4；
  - 价格只在“明显”时处理（见第 5 节）；
  - 标题 12~20 字、正文 30~38 字，按垂类（产品带品牌、潮玩带 IP、美妆突出主题），无标点无话题标签。

## 5. 合成（`runtime/compose.py`）

处理顺序：

1. **字幕范围**：文字高度 ≥1.8% 画面高，或 ≥1.2% 且在下半屏/够宽，或 ≥1.0% 且帧数多且较宽 → 才算字幕；背景漫画小字、装饰字不翻。
2. **OCR/ASR 去重**（仅保留口播时）：相似 ≥0.55、长度比 ≥0.4、较短一方 ≥6 字符 → 视为一致，**采用 OCR 译文**。
3. **口播策略**：`never`（默认，只烧画面文字）；`auto` 时画面字幕覆盖 ≥55% 也不烧；`always` 始终保留。
4. **跨轨合并**：同一时刻口播与画面文字译文相近（≥0.45 或包含关系）→ 只留画面文字那条。
5. **同刻合并**：只有开始时间差 ≤0.35s 的多条画面文字才合成一行（≤22 字，边界重复字去重）；不为避让而推后任何一条的时间。
6. **时间对齐**：重叠时只裁前一条的结束时间，裁到 <0.25s 就丢弃前一条；后一条起点永远保持原时间。
7. **文本清洗**：去标点、去价格、去关注/链接类词、剥离韩文与日文假名；中文 <2 且英文 <3 字则丢弃。
8. **抹除引流**（打码或裁切）：
   - 正则：价格/货币/折扣/优惠券 · 平台名（Instagram/YouTube/TikTok/小红书/抖音/微博/B站…）· 关注/点赞/订阅/收藏/转发/私信/链接/店铺/@/URL · 合作标签（#ad/#sponsored/#협찬/광고/협찬）；
   - 模型给的 `promo` 事件；
   - **价格只在明显时打码**：字号 ≥1.8% 画面高或宽度 ≥18% 画面宽；商品包装上的微小价格印字不处理；
   - 卡片合并：同段相邻小字行（≤28px，合并后 ≤330×300）并成一块，避免零散打码；
   - **自动水印**：同一段文字在稳定位置出现、累计 ≥60% 时长、字号小（≤3% 画面高）、且不是已翻译字幕 → 整段遮罩；
   - **边缘裁切优先**：完全落在左/右/上 14% 边距内的引流信息直接裁掉再放大回原比例（比打码美观），最多裁 20%，**底部字幕区不裁**；
   - `extra_masks.json`（质检补的遮罩）。
9. **烧录**：ffmpeg 滤镜链 = 逐框 `crop+gblur+overlay(enable between)` → `subtitles=subs.ass`。
   - 字幕：Noto Sans SC Bold、白字黑描边、单行；画面文字层在口播层上方；字号按字数与画面宽度自适应（720 宽上限 48px，1080 宽上限 72px）。
   - 编码：libx264 CRF20、AAC 128k、faststart，保留原音轨。
10. **封面**：挑画面文字最少的帧（优先靠近模型给的 coverT），顶部叠标题 + 半透明底板。
11. **字幕文件**：`中文字幕.srt`、`中外对照字幕.srt`。

## 6. 归档（`runtime/deliver.py`，整批渲染完成后）

- 按序号依次创建 `1 已完成`、`2 已完成`…（编号 = 链接顺序）。
- 成片改名成中文标题放入，同时放封面、中文字幕、中外对照、文案、meta。

## 7. 质检（`runtime/qc.py` + 文本评审 + 视觉审片）

对**成片**按 1fps 重新抽帧 OCR 并与字幕比对：

| 检查 | 判据 |
| --- | --- |
| 价格/引流残留 | 成片仍能识别到价格/联系方式（≥2 帧）→ high |
| 水印 | 顶部/底部外、稳定位置、长期出现且未翻译的常驻小字 → medium（**排除底部字幕带**，避免把自家字幕当水印） |
| 未覆盖外文 | 画面里够大的外文没有对应中文字幕 → high（一帧 ≥4 行大字视为整屏文字墙，跳过） |
| 漏译 | 事件表里有译文缺失 → high；画面字幕覆盖 ≥55% 时口播缺失不算 |
| 字幕规范 | 标点、换行、>26 字、停留 <0.45s |
| 文本评审 | 模型通读字幕+标题正文：错译/逻辑/机翻腔/活人感，给逐条改法 |
| 视觉审片 | 抽 8 帧发图给模型（deepseek-flash 支持图片输入），查漏掉的价格/水印/平台标识、字幕清晰与对位、画面与标题是否相符 |

结果写 `_work/N/qc.json`，面板逐条显示；批次顶部出现「按质检建议修改 / 保持现状」。

## 8. 返工（`index.js: fixJob / runFixes / retry`）

- `fix scope=subs`：补漏译 → 把成片复检发现的未覆盖外文补成 `extra_subs` → 补遮罩 → 重烧 → 复检。不动已润色文案。
- `fix scope=all`：在 subs 基础上，再按文本评审逐条改写问题句。
- `retry`：重跑失败条目；复用已下载视频与识别结果，识别产物缺失时重新抽帧 OCR + 翻译。

## 9. 汇总（`runtime/excel.py`）

- `本地化汇总.xlsx`：「视频清单」（序号/标题/垂类/正文/字幕数/抹除/时长/文件夹/视频/封面/字幕/原文件/语言/链接）＋「原文对照」（逐条原文与中文）。

## 11.5 投放合规（按 2026-11 会议纪要）

| 规则 | 实现 |
| --- | --- |
| 标题/正文必须体现品牌/型号 | 模型输出 `brand`/`model`；标题必须含品牌，正文尽量含型号；质检不通过则报 `brand` 类问题 |
| 禁用 AI 水文案 | 禁用词表（太炫酷/天下豪车/绝绝子/无敌了/谁懂啊/闭眼入/爱了爱了/太顶了/好看到爆/绝美/炸裂/必入/无脑入）命中即报 `copy` |
| 引流删/马赛克，品牌/型号/LOGO 保留 | 平台名、店铺、微信、链接、@ 走 promo；品牌名不进 promo，不被抹除 |
| 潮玩只收泡泡玛特（模玩/二次元周边不算潮玩） | 翻译阶段判定：**只有真潮玩**（盲盒/设计师玩具/搪胶·毛绒 IP 公仔）vertical=潮玩 且品牌不是 POP MART/泡泡玛特 → 该条标「不合格」**不出片**；**模玩**（车模/飞机/拼装模型/3D 打印模型/展示座）与**二次元周边**（动漫游戏 IP 的 T恤/海报/立牌/蓝光/画集）一律正常出片，批次结束汇总列出序号与原因 |
| 外文配中文字幕 | **只翻字幕级文字**（`textScope=important`，默认）：大标题、花字、信息卡、口播级字幕；过小装饰字与整屏文字墙不翻；商品上的纯英文保留原文；需要全翻时改 `textScope=all` |
| 垂类准入（豪车/运动/穿搭/游戏/科技数码） | 不做自动判定，由人审 |
| 既无朗读也无漂浮字幕 | 自动判定为**不合格·建议替换**，不出片，批次结束汇总序号 |
| 无朗读但有漂浮字幕 | 按 OCR 出字幕 |
| 有朗读但无画面字幕 | 判不合格·建议替换（ASR 停用） |
| 字幕风格 | 固定白字黑边，不跟随原片 |

## 11.6 质检规则（按 2026-11-22 反馈新增）

| 检查项 | 触发条件 | 处置 |
| --- | --- | --- |
| `duplicate` 重复字幕 | 同一时段两条字幕文本相似度 ≥0.72 或互相包含（定位字幕、含数字英文的除外） | 只保留一条，删掉重复 |
| `half-sentence` 半截句 | 相邻两条间隔 <0.6s，前一条以虚词结尾或只有 ≤2 字 | 合并成一句完整的话 |
| `font-size` 字号过小 | `zh.style.fontScale` < 0.95 | 提到 1.0 以上，必要时上移 |
| `mask-on-subtitle` 遮罩压字幕 | 遮罩与原片字幕框重叠 ≥12% | 收窄或下移遮罩 |
| `mask-too-large` 遮罩过大 | 单片遮罩面积 > 8% 画面 | 只框引流文字本身 |
| `watermark-unmasked` 水印没盖全 | 水印文字中心不在任何遮罩内 | 补一块遮罩 |
| `end-card` 片尾引流卡 | 成片最后 5 秒出现订阅/关注 CTA | 直接剪掉，不打码不翻译 |
| `crop-aspect` 裁切变形 | 成片宽高比与原片差 > 0.02 | 按原比例补齐再缩放 |
| `untranslated-ocr` 漏译 | 画面外文无对应中文字幕（纯拉丁/短品牌名/水印不计） | 补译或加 drop |
| `untranslated-vertical` 竖排漏译 | 见 §11.7 | 走竖排识别补齐 |

## 11.7 竖排字幕（日语/韩语花字）

macOS Vision 认不出竖排日文（旋转 ±90°、二值化、裁切都试过，返回 0 行）。可行流程：

1. RapidOCR（onnx）只跑 **det**，取 `h/w > 2.2` 且高度 > 28% 画面的竖长框；
2. 按框裁出竖排区域、放大，**逐帧人工/视觉读字**（DeepSeek 视觉可直接读竖排）；
3. 去重后写进 `zh.json` 的 `extra_subs`，时间按帧号对齐；
4. 重烧。

PaddleOCR 日文模型（japan_PP-OCRv4_rec）能下载，但在这台机器上 paddle 推理单帧 >5 分钟，暂不可用。

## 11.8 剪辑规则（按 2026-11-22 反馈）

| 场景 | 规则 |
| --- | --- |
| 边缘引流（贴边 ≤6%） | 等比裁切，保持原宽高比；超出就退回打码 |
| 画面中部引流 | 精确小框打码，**不合并成大块**，不盖原片字幕 |
| 遮罩与原字幕冲突 | compose 自动收缩遮罩：优先往上/下让开，让不开就跳过该遮罩 |
| 单片遮罩上限 | 画面面积 8%，超过说明框错，自动收成中心小框 |
| 片尾订阅/关注卡 | 直接剪掉（源视频 `-t` 截断），不留打码也不翻译 |
| 全屏引流卡（平台榜单/商品列表） | 时长 ≤5s 时建议剪掉该段；不做整屏打码 |
| 原片自带字幕 | 一律保留，中文字幕叠在下方，不遮挡 |

## 11.9 全屏引流卡自动剪裁（trimcard.py）

**自动执行**：渲染前由 `index.js` 调用 `runtime/trimcard.py --work <work> --apply`，检测到就剪、没检测到就跳过。

检测条件（全部满足才剪）：

1. 该时刻画面文字 ≥ 12 条（密度）；
2. 大字外接框从画面上半部开始（`y0 < 0.45h`）且纵向跨度 ≥ 28% 画面；
3. 覆盖面积 ≥ 28% 画面；
4. 命中平台/榜单/优惠券关键词（amazon / 楽天 / ランキング / 쿠팡 / 榜单 / 畅销 / 优惠券 / best seller 等）；
5. 连续 ≥ 0.8 秒。

剪裁时同步处理：`source_full.mp4` 备份原始素材、`events.json` 时间轴、`zh.json` 的 `extra_subs` 与 `duration`、`probe.json`、`summary.json`。字幕按剪掉的时长整体前移。

实测：本批 32 条只命中 #12 的 Amazon 榜单页（49.5–51.0s，剪掉 1.5s），其余 31 条零误报。

手动用法：

```bash
python3 runtime/trimcard.py --work <work目录>            # 只报告，不改动
python3 runtime/trimcard.py --work <work目录> --apply    # 真的剪
```

## 12. 已知边界

1. **常驻横幅片**：整屏都是同一块长期文字时，聚类会并成一条长字幕（个别片子需要固定间隔兜底）。
2. **整屏文字墙**（漫画页/海报）：按规则跳过不翻。
3. **小于画面高度 ~1.8% 的装饰字、包装微印**：不翻、不打码。
4. **纯图形水印/logo**：没有专门的目标检测，只能靠文字检测 + 常驻区域遮罩；视觉审片能“看到”但给不出精确框。
5. **文本评审是建议性质**：模型每轮都会挑出可改之处，不等于不能发。
